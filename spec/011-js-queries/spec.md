## Problem / motivation
jsoneditoronline.org's Transform dialog lets the user filter, sort and reshape data with a query,
and its documentation names "JavaScript with Lodash" as one of its two query languages
(`data = _.orderBy(data, [['address', 'city']], ['asc'])`). v1 offers Transform with JSONQuery,
JMESPath and JSONPath only (003 criterion 5): the library's JavaScript and Lodash languages run the
query with `new Function`, which the webview's CSP forbids (003 criterion 6, ADR-006), and ADR-010
left it to this spec to isolate user query code, because in the extension host it would have Node's
file and network access. The feature map lists the two languages as P1 ("JavaScript and Lodash query
languages"). Developers know JavaScript, so for many users it is the query language they can write
without looking anything up.

## Goal
In the Transform dialog the user can pick JavaScript or Lodash and write the same query text that
works on jsoneditoronline.org and in the library, with the wizard and the live preview, and the query
runs in a sealed engine that cannot reach the page, the extension host, files or the network; the
result is written back like any other transform, keeping comments.

## Terms
- **Query text:** what the user types or the wizard writes: a script that defines `function query
  (data) { … }`, as the library's `javascriptQueryLanguage` and `lodashQueryLanguage` expect. Lodash
  queries have `_` in scope and must close every `_.chain(` with `.value()` (the library's own check).
- **Engine:** QuickJS (ES2023 interpreter in WebAssembly), from `quickjs-emscripten-core` with the
  `@jitl/quickjs-singlefile-browser-release-sync` variant, running inside the editor webview (UNK-048 ★).
  A **run** is one fresh QuickJS runtime and context: Lodash (if needed) loaded, the data put in, the
  query called, the result taken out, the runtime freed.
- **Reference:** the library's own `executeQuery` of the same language, run in Node (no CSP), on the
  same data and query text.
- **Threshold:** spec 008's 5 MiB (5,242,880 bytes of UTF-8 text, UNK-014).

## Acceptance criterion (falsifiable)
`runQuery(language, data, queryText)` in `packages/app-shell` (synchronous, as the library's
`QueryLanguage.executeQuery` is) returns the result data or throws `QueryError` with a message.

1. **Same results as the library (unit, Node + engine):** for every case in `tests/query/<case>/`
   (`input.json5`, `case.json` with `language` and tags, `query.js`, then `expected.json5` or
   `error.json`), `runQuery` gives data equal to `expected.json5` under `isDeepStrictEqual` with key
   order checked, or a `QueryError` whose message contains `error.json`'s text; for every case
   without `error.json` and without a Q2 tag (criterion 2), the reference gives the same data.
2. **Coverage:** a coverage test asserts at least one case per language for each tag: `filter`,
   `sort`, `pick` (the three wizard outputs, generated by the library's `createQuery`), `map`,
   `group` (Lodash `groupBy`), `scalar-result`, `undefined-result`, `nested-root` (a query on a
   selected node), `syntax-error`, `thrown-error`, `chain-without-value` (Lodash), and for Q2 each of
   `nan`, `infinity`, `minus-zero`, `proto-key`, `bigint-result`, `cyclic-result`, `date-result`,
   `function-result`.
3. **Exact data (fast-check, seed committed, 10 000 runs):** for any data the 002 formats can hold
   (JSON5 values, `-0`, `NaN`, `±Infinity`, duplicate-free objects with any keys including
   `__proto__`, nesting to depth 64), the identity query `function query (data) { return data }`
   returns data equal to the input under `isDeepStrictEqual` with key order checked, in both
   languages.
4. **Sealed (web, `pnpm test:web`, other origins blocked):** each query in
   `tests/query/sealed/*.js` runs in the dev host's Transform dialog and its preview shows
   `"undefined"` for `typeof` of each of `window`, `document`, `self`, `globalThis.fetch`,
   `XMLHttpRequest`, `WebSocket`, `importScripts`, `postMessage`, `acquireVsCodeApi`, `require`,
   `process`, `setTimeout`, `WebAssembly`, `Worker` and `navigator`; a query that calls `eval` or
   `Function` runs only inside the engine. During those runs no request is made (the fixture's
   blocked-origin check), the dev host receives no message, and the page's DOM outside the dialog's
   preview is unchanged.
5. **Limits (web):** a run is stopped after 5 seconds or 256 MiB of engine memory. `while (true) {}`
   in the preview shows "The query was stopped after 5 seconds." within 6 seconds of the run starting;
   a query that keeps allocating shows "The query used more than 256 MiB and was stopped." within
   15 seconds; after either, the editor responds to a click within 500 ms and the next query runs.
   Neither changes the document.
6. **Errors:** a syntax error, a thrown error, a missing `query` function and a Lodash chain without
   `.value()` each show their message in the dialog's preview (the library's error display), and
   Transform is disabled; the document is unchanged.
7. **Write-back (e2e):** with JavaScript and with Lodash, Transform on
   `tests/e2e/fixtures/query/<case>/input.{json,jsonc,json5}` (the whole document in text, tree and
   table modes, and a selected node in tree mode) leaves the document text byte-equal to
   `expected.*`: written through the existing data-change path (002 R14), so comments on surviving
   members stay; the document is dirty and not saved, and one undo restores the previous text exactly.
8. **Languages and wizard (web):** the Transform dialog lists JSONQuery, JMESPath, JSONPath
   (Goessner), JavaScript and Lodash, in that order, JSONQuery the default as today. Picking
   JavaScript or Lodash and using the wizard's filter, sort and pick fields fills the query box with
   the library's `createQuery` text for that language and the preview shows its result.
9. **CSP and offline:** the editor webview's CSP is 003 criterion 6's with one change (UNK-048 ★):
   `script-src` is the nonce plus `'wasm-unsafe-eval'`; it still has no `'unsafe-eval'`, no
   `'unsafe-inline'` and `connect-src 'none'`. The engine's WebAssembly is inside the script bundle,
   so nothing is fetched. `pnpm check:offline` passes; any URL the new bundles add is listed in
   `offline-allowlist.txt` by name with the Reviewer's sign-off (AGENTS rule 3). The CSV, compare and
   convert panels keep 003 criterion 6 exactly.
10. **Loading (web):** the editor shows the document before the engine's WebAssembly is compiled (the
    engine is compiled only when the Transform dialog first opens; a test hook records both moments).
    Opening Transform the first time waits for the engine, then opens the dialog.
11. **Large files (e2e, per UNK-049 ★):** in a large-file tab unlocked with "Edit anyway" (008
    criterion 4) the Transform dialog lists JSONQuery, JMESPath and JSONPath only; a locked tab offers
    no Transform at all (008 criterion 2).
12. **Speed (bench):** `bench/RESULTS.md`, regenerated in one run, gives the median time of one
    run of the bench queries (`bench/query/*.js`: filter-map in JavaScript, filter-orderBy-map in
    Lodash) at 1 and 5 MiB in the engine beside the reference. HYPOTHESIS (sandbox check, Node 22,
    QuickJS 0.32.0): 5 MiB takes about 0.4 s in JavaScript and 1.1 s in Lodash, against 0.1 s for
    the reference, inside the 5-second limit. If a bench query at 5 MiB exceeds 2.5 s on the CI
    runner, an UNKNOWN goes to the owner before T4 merges.
13. **Licenses:** `quickjs-emscripten-core` and `@jitl/quickjs-singlefile-browser-release-sync` at
    exactly 0.32.0 (MIT) and `lodash` at exactly the version of the `lodash-es` the library already
    ships (4.18.1, MIT) are runtime dependencies of `app-shell`; `pnpm check:licenses` passes and
    `THIRD_PARTY_LICENSES.md` lists them, QuickJS's own MIT notice included.

## Query rules (golden cases encode these)
- **Q1 Input:** the query gets a fresh copy of the data (of the selected node, for a node) built
  inside the engine; nothing it does to that copy reaches the editor except through its result.
- **Q2 Values:** numbers, strings, booleans, `null`, arrays and objects pass in and out exactly, with
  key order, `-0`, `NaN`, `Infinity`, `-Infinity` and `__proto__` keys kept (criterion 3). A result of
  `undefined` becomes `null`, as in the library. Out of the engine, a value JSON cannot hold follows
  `JSON.stringify` (a `Date` becomes its ISO string; a function, symbol or `undefined` member is
  dropped; one in an array becomes `null`), except that a `BigInt` or a cycle is a `QueryError`
  ("The result has a BigInt, which JSON can't hold." / "The result refers to itself.").
- **Q3 Scope:** the engine's global object has the ECMAScript built-ins and, for Lodash, `_`; nothing
  else. `Date.now()` and `Math.random()` work; there are no timers, no `console`, no modules.
- **Q4 Isolation of runs:** every preview and every Transform is its own run; nothing a query stores
  on the global object is seen by the next run.
- **Q5 Writing the result:** Transform hands the result to the library exactly as the library's own
  languages do; from there the existing paths write it (text mode: `data-change.ts`; tree and table:
  the library's patch, sent as data when it replaces a container), so the formats, comments and
  number writing of 002 apply unchanged. A result the document's format cannot hold (for example
  `NaN` into `.json`) is handled as it is today for JSONQuery results.

## Where we differ from jsoneditoronline.org
- The site runs JavaScript and Lodash queries with `new Function` on the page. We run them in QuickJS:
  the same query text and results (criterion 1), about 3–4 times slower (criterion 12), with time and
  memory limits the site does not have (criterion 5).
- The site's queries can use browser objects (`window`, `fetch`); ours cannot (criterion 4).
- Above 5 MiB we offer only the native languages (UNK-049 ★).

## Scope
- **In:** `runQuery` and the engine wrapper in `app-shell`, the JavaScript and Lodash `QueryLanguage`s
  (the library's `createQuery`, our `executeQuery`), the value bridge (Q2), limits and messages, the
  CSP change and its e2e check, lazy loading, the query corpus and property suite, the sealed and
  limits web tests, write-back e2e, the large-file rule, the bench, licenses.
- **Out:** saved or named queries; remembering the last language (spec 019, Settings); a query
  console or REPL; queries on several documents; async queries (`await`, `fetch`); user-provided
  libraries other than Lodash; RFC 9535 JSONPath (014); lossless big numbers (015); the vscode.dev
  build (013) and the Chrome app (020), which reuse `runQuery` with the app-shell but get their own
  CSP checks in their specs; Ajv, which stays in the extension host (ADR-010).
