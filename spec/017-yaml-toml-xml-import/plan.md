# PLAN 017 — YAML, TOML and XML import

> Derives from spec `017`. Constraints from `governance/constitution.md`
> (D3 observable behavior, D4 reversibility).

## Approach
The importer is one module per kind in `packages/core/src/import/` (`yaml.ts`, `toml.ts`,
`xml.ts`) behind `importData(text, kind)`, exported from `@chr-json-editor/core`, so the desktop
host, the web host and a later Chrome app share it. Parsing is the libraries' job; turning their
output into our data is ours, because that is where the spec's rules live:

- **YAML:** `parseAllDocuments(text, { intAsBigInt: true, merge: true, uniqueKeys: false,
  maxAliasCount: -1, prettyErrors: false })`, then our own walk over each `Document`'s nodes (not
  `toJS`): scalars get A2's decimal text from `text.slice(node.range[0], node.range[1])` for plain
  numbers, keys follow Y4, aliases are resolved by copying with a running count of added values
  (Y6's limit replaces the library's `maxAliasCount`, whose cut-off is not ours to tune), tags
  outside the core schema are read as untagged (Y7, collected from the library's
  `TAG_RESOLVE_FAILED` warnings and from the node `tag`s it does resolve, such as `!!binary`). A
  `%YAML 1.1` document uses the library's `yaml-1.1` schema without its timestamp tag (Y1).
- **TOML:** `smol-toml`'s `parse(text, { integersAsBigInt: 'asNeeded' })`, then a walk that turns
  `BigInt` into a number or big number value (A2), `TomlDate` into `toISOString()` (TM4) and
  non-finite floats into `null` with a warning (A3). TOML errors carry line and column
  (`TomlError`).
- **XML:** a `saxes` `SaxesParser` with `xmlns: false`; our handlers build XM1–XM8's shape on an
  explicit stack (so A5 is a counter, not a stack overflow), decode only what `saxes` decodes, and
  turn its "undefined entity" error events into XM7's warning while every other error event ends
  the conversion with XM8's error.

Every walk uses an explicit stack and `Object.defineProperty` for keys (A4, A5). Numbers go through
one helper, `numberFromDecimalText`, that spec 015 T2's `isSafeNumber` check backs, so the three
kinds and spec 015 agree on what a big number is.

The commands live in `packages/vscode-extension` and reuse the convert command's file writing
(spec 006 T3, UNK-035: `workspace.fs` beside the source, save dialog when the file exists,
untitled fallback as spec 016 T3 adds it) and spec 009 T4's "Replace Document Data" path (002
R14). No webview change: the extension host reads the file and writes the result. The libraries
are bundled into both host entries (`dist/extension.js`, `dist/web/extension.js`) and never into
the webview bundle.

Big numbers need spec 015 T2's `LosslessNumber` in core data and `stringify`; the corpus can be
written first, since its expected files are text.

## Constraints / invariants
- No overwrite without snapshot/backup (D4): never writes over an existing file without the save
  dialog; the source file is never changed; "Import YAML, TOML or XML…" asks first and is one
  undoable edit.
- Offline (AGENTS rule 3): nothing is fetched; XML external entities and DTDs are never read
  (XM7); every new `check:offline` allowlist entry is named by the Reviewer.
- `core` stays free of DOM and Node APIs (spec 013); the commands use `workspace.fs`.
- Hostile files fail fast and bounded (Y6, XM7, A5) rather than hanging or exhausting the host.
- Expected files in the corpus are written by hand from the rules, never generated by the importer.

## Risks and mitigations
| Risk | Mitigation |
|---|---|
| R1 `yaml` is slow and memory-hungry (5.4 s, 0.4 GB at 5 MiB; ~1 min, 4 GB at 50 MiB) and blocks the extension host while it runs | the YAML limit (UNK-077) from CI numbers; progress notification above the threshold; `js-yaml` is faster but fails the license rule (argparse, Python-2.0). If a later version of `yaml` or a licensed alternative is faster, raising the limit is a delegated re-measure, not a spec change |
| R2 Our own walk over `yaml`'s nodes diverges from the library's `toJS` | the round-trip property (criterion 3) and the corpus; the walk only adds A2, Y4, Y6, Y7 on top of node values the library resolves |
| R3 XML has no single standard mapping; users may expect another shape | UNK-075 (owner); the rules are fixed in the corpus; a different shape later is an option, not a silent change |
| R4 TOML datetimes lose sub-millisecond digits (TM4) | allowed by TOML 1.0.0 and stated in the spec; a `toml-dates` case pins the output |
| R5 New dependencies bring URLs into the bundle | criterion 12: each allowlist entry named by the Reviewer; the libraries are host-only |
| R6 A merged 015 T2 is needed for big numbers | T2 needs 015 T2; T1's corpus is text and can land first |
